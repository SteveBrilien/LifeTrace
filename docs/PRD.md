# LifeTrace 产品需求文档

版本：v0.1  
状态：需求基线

## 1. 产品目标

LifeTrace 帮助用户低摩擦地记录每天发生的事情，并把照片、文字、时间和空间位置组织成可回看的个人时间线与地图轨迹。

首版成功标准不是功能数量，而是：记录可靠、离线可用、位置可信、数据私密。

## 2. 目标用户

- 当前仅供项目所有者本人使用
- 不设计公开注册、好友、点赞、评论或内容推荐
- 架构不主动阻断未来多设备同步，但不为多用户平台增加复杂度

## 3. 核心场景

### 3.1 创建日记

用户可以：

- 输入文字
- 拍摄或选择 1～9 张照片
- 自动记录创建时间，并允许手动修正
- 自动获取当前位置，并允许在地图上手动修正
- 在无网络时保存

### 3.2 浏览与管理

- 按时间倒序查看日记
- 查看日记详情和原图
- 编辑或删除日记
- 清楚看到本地保存、等待同步、同步成功或同步失败状态

### 3.3 查看地图

- 按单日或日期范围查看轨迹
- 按时间顺序连接有效轨迹点
- 以独立标记显示日记位置
- 点击标记查看照片缩略图和文字摘要
- 对定位缺口和低精度片段做明确提示，不伪造轨迹

### 3.4 后台轨迹

- 用户主动开启后，应用通过前台定位服务持续记录
- 运动时提高采样频率，静止时降低采样频率
- 依据精度、距离、速度和时间过滤漂移点
- 通知栏持续显示定位状态
- 用户可以随时暂停
- 设备重启或被系统杀死后，应用应清楚提示是否恢复成功

## 4. 页面结构

| 页面 | 首版职责 |
|---|---|
| 日记 | 时间线、同步状态、快速新增入口 |
| 新建/编辑 | 文字、照片、时间、位置 |
| 日记详情 | 完整内容、编辑、删除 |
| 地图 | 日期筛选、轨迹线、日记标记 |
| 设置 | 定位、同步、隐私、存储与诊断 |

底部导航固定为“日记、地图、设置”，新增日记使用悬浮按钮。

## 5. 隐私与安全

- 默认使用生物识别或设备凭据解锁
- 所有网络传输使用 HTTPS
- 同步前在客户端加密正文、照片元数据、位置和轨迹
- 加密恢复密钥由用户导出并离线保存
- 日志不得记录正文、精确坐标、密钥或照片内容
- 位置信息仅在用户明确授权后采集

## 6. 首个里程碑范围

### 包含

- Compose 基础界面
- 本地日记新增、浏览、编辑和删除
- 本地图片导入与缩略图
- 自动时间戳
- 前台获取当前位置
- Room 持久化
- 基础错误状态与空状态

### 暂不包含

- 后台连续定位
- 轨迹地图
- 云端同步
- 端到端加密实现
- 天气、AI 总结、统计回顾
- 多用户和社交功能

## 7. 首个里程碑验收标准

1. 飞行模式下能够创建带文字、照片、时间和位置的日记。
2. 强制关闭并重新打开应用后，日记仍然存在。
3. 能够查看、编辑和删除日记。
4. 拒绝位置权限时仍可保存日记，并允许手动补充位置。
5. 图片导入失败或存储不足时给出可理解的错误提示。
6. 所有核心操作不依赖服务器可用性。

## 8. 非功能目标

- Android 9（API 28）及以上
- 目标 SDK 跟随可用的最新稳定 Android SDK
- 冷启动目标小于 2 秒（中端设备、数据量较小时）
- 常规浏览不得阻塞主线程
- 后台定位阶段以日常续航可接受为硬性验收项
- 数据库和同步协议必须支持版本迁移
